## 5. 완료된 항목 기록: B. 대기 시간 측정 기준 변경

- **요청 내용:** 대기 시간을 처음 접수 시각(`queued_at`)이 아니라, 처리 가능해진 시각(`next_attempt_at`)부터 재기.
- **반영:** `a3484f0` "fix: measure claimable backlog and guard deferred work"
  - `oldest_due_age()`: `pending`·`retrying`·`waiting_context` 중 지금 처리할 차례가 된 기록만, 상태별로 `(state, next_attempt_at)` 인덱스를 써서 계산합니다. 작업자가 처리할 기록을 고르는 조건(`claim_batch`)과 같습니다.
  - 5분 넘게 갱신 없는 `processing` 기록은 `processing-stale` 오류 경고로 분리했습니다. 서버 알림 현황 탭에도 자동으로 표시됩니다.
  - `claim_batch`가 처리할 기록을 고른 뒤 실제로 가져가기 전에 재시도 시각이 미뤄지면 그 기록은 가져가지 않습니다.
- **서버 검토 결과:** 코드 검토에서 이상 없음. 파이프라인 pytest 122 통과(PyMongo 4.10.1, mongomock 4.3.0 고정). 서버 영향 없음.
- **참고:** 관측 이력 차트의 `oldest_due_age_s`는 16:22 KST(관측소 재시작)부터 기준이 바뀝니다.
